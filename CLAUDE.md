# CLAUDE.md — контекст проекта ABRA

Этот файл читается ИИ-ассистентом (Claude Code) в начале каждой сессии в этом репозитории. Держи его в актуальном состоянии: когда меняется архитектура, добавляется компонент или переносится деплой — обнови соответствующий раздел здесь и в `ARCHITECTURE.md`.

## Что это за проект

Одностраничный лендинг-визитка "ABRA" — персональный бренд-сайт для позиционирования "архитектор систем роста" (маркетинг + продажи + аналитика + продукт как единая система). Целевое действие — заявка на бесплатный 30-минутный видеозвонок через форму или mailto.

- Прод: `https://a-bra.ru/` (VPS, FirstByte, Москва — см. раздел «Деплой»)
- Репозиторий: `https://github.com/abrathecreator/abra`
- Владелец контента: Утяшев А. Р.
- Язык интерфейса: русский (`<html lang="ru">`)

## Стек

- **Vite 6** — сборка, dev-сервер, multi-page build
- **Vanilla JS** (ES-модули, без фреймворка) — весь интерактив
- **GSAP 3 + ScrollTrigger** — вся анимация раскрытия по скроллу
- **Canvas 2D** (не Three.js/WebGL) — созвездие на фоне hero. Three.js использовался раньше, заменён на Canvas 2D ради размера бандла (было 579.72KB/163.65KB gzip → стало 120.40KB/47.63KB gzip)
- CSS — один файл `src/style.css`, без препроцессора, без Tailwind. Дизайн-токены через custom properties в `:root`
- Приём формы — собственный PHP-скрипт (`server/contact.php` в репозитории → `/opt/abra/contact.php` на сервере), не Formspree (от него отказались 12.09.2026 при переезде — см. «Деплой» и `TECHDEBT.md`)
- Яндекс.Метрика — аналитика, id `111833820`

Зависимостей в `package.json` всего одна прод (`gsap`) и одна dev (`vite`). Никакого React/Vue/бандлера компонентов — так и должно оставаться, если явно не попросят обратное.

## Дизайн-токены (`:root` в `src/style.css`)

```css
--bg: #0C0B09;          /* основной тёмный фон */
--bg-warm: #131210;      /* чуть теплее — карточки, поля форм */
--accent: #B87333;       /* медный/янтарный акцент — ЕДИНСТВЕННЫЙ цвет для hover/фокуса/результата */
--text: #CEC9C3;         /* приглушённый текст, вторичный */
--snow: #EDEBE6;         /* яркий текст — заголовки, важные лейблы */
--border: rgba(206,201,195,0.07);        /* 1,11:1 — ТОЛЬКО декоративные линии и разделители */
--border-control: rgba(206,201,195,0.45); /* 3,25:1 — границы полей, чекбоксов, .nav__cta, .info-btn */
--border-surface: rgba(206,201,195,0.16); /* края плавающих плашек: нижняя панель, шторка, cookie-карточка на телефоне */
--nav-h: calc(84px + env(safe-area-inset-top)); /* высота шапки с безопасной зоной — scroll-margin-top, липкие панели */
--font-display: "Syne", "Inter", system-ui, sans-serif;  /* заголовки, лейблы, кнопки */
--font-body: "Inter", system-ui, sans-serif;               /* обычный текст */
--max-w: 1240px;
--gutter: clamp(20px, 4vw, 56px);
```

Два токена границ разведены намеренно: `--border` не берёт норму WCAG 3:1 и годится только для тонких декоративных линий, `--border-control` — для всего, что человек должен разглядеть и во что должен попасть. Не сводить их обратно в один и не подменять одно другим: 29 использований `--border` — это разделители, 4 использования `--border-control` — поля формы, чекбоксы, кнопка в шапке и кнопки «?» в калькуляторе.

Правило проекта: **новый цвет не вводится**, любой новый UI-элемент красится через существующие токены (в т.ч. `rgba()` на основе `--text`/`--accent`, как сделано для `--icon-base`/`--icon-guide`). Секция «Философия» раньше была единственной с инвертированной светлой темой (`--snow`-фон), это было сознательно откатано — весь сайт сейчас на едином тёмном фоне.

`hero` → `insight` → `system` → `services` → `method` → `case` (тизер кейса, `.case-teaser`) → `philosophy` → `cta` (id="cta") → `contact`. Нумерация больше не отображается текстом — см. ## Сквозная шапка (`.nav`) и нижняя панель (`.tabbar`)

С 15.09.2026 навигация одинакова на всех 10 страницах и не содержит якорей на секции главной. Спецификация — `docs/superpowers/specs/2026-09-15-navigation-and-button-system-design.md`.

**Шапка (>720px).** Логотип, три ссылки `.nav__links` — «Главная» (`%BASE_URL%`), «Кейсы» (`%BASE_URL%cases`), «Статьи» (`%BASE_URL%articles`) — и «Написать» (компактные скобки, уровень 2 системы кнопок), который раскрывает `.nav__contact-menu` с телефоном и почтой.

**Текущий раздел** — `aria-current` на ссылке шапки и на вкладке панели, выглядит как подчёркивание (уровень 3):

| Страница | Пункт | Значение |
|---|---|---|
| index | Главная | `page` |
| cases | Кейсы | `page` |
| case-zhbi | Кейсы | `true` |
| articles | Статьи | `page` |
| growth-system | Статьи | `true` |
| unit-economics, privacy, terms, consent, 404 | — | — |

Новая страница внутри раздела получает `aria-current="true"` на пункте раздела; страница вне разделов — без атрибута.

**Телефон (≤720px).** Шапка — только логотип; `.nav__links` и `.nav__contact` скрыты. Гамбургера нет — удалён 15.09.2026. Навигация — `.tabbar`, плавающая панель у нижнего края: три вкладки и «Написать» (`.abra-cta` уровня 1; ссылка на `%BASE_URL%#contact`, с JS открывает шторку `#contact-sheet`). Разметка панели и шторки стоит сразу после `</header>` и одинакова во всех 10 файлах, кроме `aria-current` и варианта кнопки «Оставить заявку».

**Панель прячется** при прокрутке вниз дальше 90px и возвращается при прокрутке вверх и у конца страницы (класс `is-hidden`, логика в `nav.js`); при `prefers-reduced-motion` не прячется. Отдельно она скрыта через `visibility: hidden` (класс `is-suppressed`), пока открыта шторка или модалка или фокус в текстовом поле — причины собирает `src/tabbar-state.js`. Снятие скрытия синхронное: сначала панель видима, потом возвращается фокус — на скрытый элемент фокус не встаёт.

**Слои `z-index`:** шапка 20, меню «Написать» 30, панель 35, cookie-баннер 40, шторка 45, подсказка калькулятора 50, модалка 60, skip-link 100.

**Безопасная зона iPhone.** Во всех файлах `viewport-fit=cover`; шапка учитывает `env(safe-area-inset-top/left/right)`, панель, шторка и cookie-карточка — `env(safe-area-inset-bottom)`. На ≤720px cookie-баннер — карточка над панелью, футер получает нижний отступ под панель (правило `padding-bottom` стоит в `style.css` сразу после базового `.footer {}` — иначе тот же селектор ниже по каскаду его перебивает), портрет в hero ограничен `clamp(200px, 30svh, 260px)`. На 390×844 «Разобрать систему» помещается над панелью на первом экране; на невысоких реальных вьюпортах вроде 375×667 (iPhone SE) содержимое hero выше экрана и кнопка остаётся под сгибом даже без панели, как и раньше — после короткого скролла вниз панель прячется (порог 90px), и кнопка становится видна целиком. По той же причине с каскадом сразу после базового `.hero__sub {}` стоит и её собственное правило отступов на ≤720px.

При правке шапки, панели или шторки — менять разметку во всех 10 файлах и прогонять `npm test`: он сверяет, что панель и шторка совпадают.

## Фирменный текстовый стиль меток разделов

Owner попросил заменить нумерацию на персональный формат: **`[ .Название ]`** — квадратная скобка, пробел, точка вплотную к слову, пробел, закрывающая скобка. Пример: `[ .Система ]`. Применено ко всем 7 меткам разделов (текст внутри `.tag`). Не отступай от этого формата в новых разделах без явной просьбы — это осознанный брендинг, не случайность.

## Компонент `.abra-cta` — фирменная кнопка

Уровень 1 системы кнопок (таблица ниже). «Написать» в шапке — та же `.abra-cta` с модификатором `--compact`, отдельного компонента пилюли больше нет. Концепция: **уголки-скобки достраиваются в полную рамку при hover**, никакого terminal/loading текста (это было в более ранней версии и осознанно убрано).

- Custom properties на `.abra-cta`: `--cta-h`, `--cta-pad-x`, `--cta-bracket-span`, `--cta-corner-h/w`, `--cta-shift`, `--cta-stroke`
- 4 угла (`.abra-cta__corner--tl/tr/bl/br`) растут до `calc(50% + 1px)` по ширине на hover/focus-visible — это и есть "скобки → рамка"
- **Стрелки в кнопке НЕТ** — убрана по просьбе owner'а вместе с текстом лейбла центрированным (`justify-content` не нужен: убрали зарезервированный под стрелку отступ, паддинг `--cta-pad-x` уже симметричный)
- `@media (hover:hover) and (pointer:fine)` для десктопного hover, `@media (hover:none)` — эквивалент через `:active` на тач-устройствах
- `data-state="loading"` — JS-управляемое состояние во время submit формы (`contact-modal.js`)

`.abra-link` — вторичная кнопка-компаньон ("Посмотреть услуги"), сознательно сделана тихим текст-линком (не второй `.abra-cta`), чтобы не спорить визуально с первичной кнопкой.

**Четыре кнопки — четыре разных текста, и это осознанно.** Раньше на всех стоял один лейбл «Разобрать систему», а нажатие давало то скролл, то почтовый диалог, то отправку данных. Сейчас: шапка — «Написать», hero — «Разобрать систему» (фирменная фраза остаётся за ним), секция `cta` — «Перейти к форме», submit — «Отправить заявку». `aria-label` каждой совпадает с фактическим действием. Не сводить обратно к одному тексту.

**Кнопка «Написать» в шапке (добавлено 13.09.2026) — теперь не ссылка на `#cta`, а `<button>`, раскрывающий список способов связи.** По клику показывает `.nav__contact-menu` с двумя пунктами: `tel:+79110256443` и `mailto:info@a-bra.ru`. Логика в `nav.js` (`initNav()`, поиск по `.nav__contact`, до 15.09.2026 жила прямо в `main.js`): Escape закрывает и возвращает фокус на кнопку, клик снаружи тоже закрывает — тот же паттерн, что у подсказок «?» в калькуляторе юнит-экономики, ради единообразия по всему сайту. Визуально меню — `.info-tip`-подобная плашка (`--bg-warm`, `--border`, radius 10px), новых цветов не вводилось. Не путать с кнопкой `cta` в одноимённой секции — та по-прежнему ведёт на форму.

Кнопка в разделе `cta` ведёт **на форму** (`href="#contact"`), а не в `mailto:`. Прямой почтовый канал вынесен под неё отдельной тихой строкой `.cta__direct` с `.abra-link--accent` на `mailto:info@a-bra.ru`. Доменный ящик заведён 13.09.2026 (Ru-Center/nic.ru, см. «Форма обратной связи») — адрес обновлён здесь и во всех юридических страницах (`privacy.html`, `terms.html`, `consent.html`, `404.html`); личный Gmail `artemutyashev@gmail.com` больше нигде на сайте не фигурирует. Домен `abra.systems` посторонний, в репозитории его быть не должно.

### Система кнопок — четыре уровня (с 15.09.2026)

Чем важнее действие, тем больше у кнопки рамки.

## Система иконок разделов (`section-icons.js` + `icons.js`)

Полностью авторская SVG-система, 7 уникальных иконок (не библиотека). Каждая иконка = **STATIC MEANING + MOTION MEANING** (статика показывает суть, motion её проигрывает).

- Единый `viewBox="0 0 64 64"` на все 7
- Общие CSS-классы: `.icon-base` (статичная геометрия), `.icon-guide` (едва видимые направляющие, "дорисовываются" через `stroke-dasharray/dashoffset` с `pathLength="1"` для упрощения расчётов), `.icon-fill`/`.icon-stroke` (элементы, которые переходят из приглушённого в акцентный цвет)
- Типы: `insight` (скобки+точка, диагонали сходятся к центру), `system` (сетка выравнивается), `services` (3 слоя расходятся), `method` (сигнал идёт по маршруту из 4 узлов), `philosophy` (внешний контур гаснет, ядро усиливается), `connect` (два блока сближаются), `contact` (скобки расходятся, target-ring)
- Размер: `--icon-size: clamp(36px, 6vw, 58px)` — единая переменная на `.section-icon`
- **Reveal-логика**: `IntersectionObserver` (threshold 0.3) добавляет класс `.is-revealed` при первом появлении в viewport и **больше никогда его не убирает** (важно: раньше был `setTimeout` на откат к дефолту — owner явно попросил убрать откат, иконка должна "остаться завершённой")
- Hover/focus на десктопе (`@media (hover:hover) and (pointer:fine)`) использует те же CSS-правила конечного состояния, что и `.is-revealed`
- `prefers-reduced-motion: reduce` — иконка остаётся полностью статичной, JS вообще не запускает `IntersectionObserver`-цикл, в CSS все `transition-duration`/`animation` обнулены
- Все длительности/задержки в CSS-блоке "SECTION ICONS" **удвоены** относительно первоначального дизайн-брифа (owner попросил "медленнее в 2 раза" уже после первой реализации) — если снова просят "быстрее/медленнее", меняй `ms`-значения пропорционально по всему блоку, не только у одной иконки, иначе хореография между hover-состояниями/reveal рассинхронизируется
- Философия больше не на светлом фоне — `.philosophy .section-icon` override с `--icon-base`/`--icon-accent` под светлую панель был удалён вместе с самой светлой панелью

## GSAP-анимации (`main.js`)

**Первое, что делает `main.js` — развилка по `prefers-reduced-motion`.** Если человек попросил ОС уменьшить анимацию, не создаётся ни одного твина и ни одного ScrollTrigger. Это не косметика: каждый `gsap.from()` выставляет своему элементу `opacity:0` в момент создания, поэтому раньше при `reduce` весь контент ниже первого экрана был физически скрыт и не появлялся даже после прокрутки. Не заводя твинов, мы оставляем всё в состоянии из CSS — видимым.

- `.philosophy__mark` в этой ветке **не трогаем**: у него собственная непрозрачность `0.03` в CSS, принудительный `opacity:1` сделал бы огромную букву «A» непрозрачной
- `updateFunnelArrows()` и обработчик submit формы живут **выше** развилки — к движению они отношения не имеют и обязаны работать в обеих ветках
- `hero.js` тоже уважает настройку: созвездие рисуется один раз и замирает, параллакс от курсора не подключается, при ресайзе статичный кадр перерисовывается вручную
- Проверять A/B: поднять второй dev-сервер на предыдущем коммите через `git worktree` и сравнить `opacity` блоков при `--force-prefers-reduced-motion`


- Один `gsap.timeline()` на вход hero (nav → eyebrow → title строки → subtitle → sub → actions → scroll-подсказка), с фолбэком через `try/catch` и safety-net `setTimeout` (2500мс), который принудительно показывает всё, если что-то зависло с `opacity:0`
- `ScrollTrigger` на `.section__head`, `.funnel`, `.cards`, `.services__grid`, `.step`, `.philosophy__title/text/mark` (последний — `scrub`-параллакс), `.cta__inner`, `.contact__inner` — везде паттерн "on enter: y+opacity from"
- `updateFunnelArrows()` — прячет стрелку у элемента, который визуально стал первым в новой строке/новом ряду. Пересчитывается на `resize`, `load` и `document.fonts.ready` (шрифт Syne грузится асинхронно и до его загрузки ширина текста другая → неправильные точки переноса — это уже было один раз починенной багой, не убирай `fonts.ready`-обработчик)

## Воронка (`.funnel`, раздел Insight)

- Десктоп/таблет (>560px): `flex-flow: row wrap; justify-content: center` — центрированные строки, `updateFunnelArrows()` скрывает "осиротевшую" стрелку у первого элемента новой строки
- **Мобиле (≤560px)**: `flex-direction: column` — вертикальный список сверху вниз, стрелки развёрнуты вниз (пересобраны из `border-right+border-bottom, rotate(45deg)` вместо `border-top+border-right`). На этой ширине стрелки **принудительно** `display:block !important`, потому что `updateFunnelArrows()` иначе спрятал бы вообще все (каждый элемент в column-layout имеет свой уникальный `top`, JS думает, что это N новых строк)

## Форма обратной связи (`#contact-form`)

Логика модалки (открытие/закрытие, фокус-ловушка, Escape, отправка формы, `ym_client_id`/UTM/`time_on_site_seconds`) вынесена в отдельный модуль `src/contact-modal.js` (рефакторинг 14.09.2026 — раньше жила прямо в `main.js`). Причина: `growth-system.html` (и любая будущая статья на `article.js`) тоже открывает эту форму модалкой поверх страницы, как на главной, а не уводит на `index.html#contact` — своя копия разметки `#contact-modal` в каждой такой странице (см. её в `growth-system.html`), но открывающая/отправляющая логика одна на всех через `initContactModal()`. `main.js` и `article.js` оба импортируют и вызывают её. Если меняешь что-то в контакт-форме — правь `contact-modal.js`, а не `main.js`.

Шторка «Написать» (`#contact-sheet`, ≤720px) открывает модалку через `openContactModal(opener)` из `contact-modal.js`; `opener` — «Написать» в нижней панели, на него возвращается фокус после закрытия модалки. Функция возвращает `false`, если на странице нет `#contact-modal`; на таких 6 страницах (privacy, terms, consent, 404, cases, articles) «Оставить заявку» в шторке — ссылка на `%BASE_URL%#contact`. Модалка при открытии скрывает нижнюю панель (`setTabbarSuppressed("modal", true)`) и возвращает её до возврата фокуса.

- Поля: **Имя** (`name="name"`, required), **Номер телефона** (`name="phone"`, `type="tel"`, required, placeholder `+7 999 123-45-67` — раньше было поле "Компания", заменено по просьбе owner'а), **«Куда ещё можно написать»** — два чекбокса `name="messenger"` со значениями `Telegram` и `Max` (опционально), **чекбокс согласия** (`name="consent"`, required). Форма сознательно короткая: длинных текстовых полей ("проблема", "что пробовали", "ссылка на сайт") в ней нет и не было решено возвращать — не добавляй их без явной просьбы owner'а
- Honeypot: скрытое поле `_gotcha` (антиспам, не показывать/не убирать)
- Обязательные поля помечены звёздочкой `.field__req` в `--accent` с `aria-hidden="true"` (скринридеру про обязательность сообщает сам атрибут `required`, дублировать символом не нужно); группа мессенджеров подписана «— по желанию» через `.field__optional`

- `.contact__form[hidden] { display: none }` — обязательное правило. Без него `display:grid` перебивает браузерное `[hidden]`, и после успешной отправки форма остаётся на экране рядом с блоком «спасибо»
- Плейсхолдеры во всех текстовых полях гаснут по фокусу (`opacity:0` на `:focus`), не только когда начали печатать — так пользователь сразу понимает, что пример исчез
- Submit — AJAX `fetch()` на **собственный `/contact.php`** (`action="/contact.php"`, тот же origin — до 12.09.2026 форма шла на Formspree, отказались от него при переезде на VPS ради 152-ФЗ: теперь ПДн не покидают сервер даже транзитом через сторонний SaaS). Перед отправкой — ручная проверка чекбокса согласия (на случай обхода браузерной валидации)
- `server/contact.php` (копия того, что реально исполняется на сервере как `/opt/abra/contact.php`, деплоится туда вручную, не через CI — см. «Деплой»): проверяет honeypot `_gotcha` (если заполнен — тихий `200` без обработки и без записи в лог), валидирует `name`/`phone`/`consent` на бэкенде, **сначала** пишет заявку в `/var/log/abra-contact/submissions.log` на сервере, и только потом best-effort пытается уведомить двумя параллельными каналами — письмом через собственный SMTP-клиент и Telegram-ботом через Bot API — в таком порядке специально, чтобы ни один из каналов не мог потерять заявку. Получатель и отправитель письма — доменный ящик `info@a-bra.ru` (Ru-Center/nic.ru, заведён 13.09.2026, закрывает пункт из TECHDEBT.md про временный Gmail): письмо шлётся через `mail.nic.ru:465` тем же самым ящиком самому себе, читается через вебмейл nic.ru или обычный почтовый клиент (IMAP `mail.nic.ru:993`, SSL). На сервере нет ни одного почтового демона (ни postfix, ни sendmail) и нет расширения curl — поэтому `contact.php` говорит по SMTP сам, вручную, через `stream_socket_client()` с TLS. Логин/пароль ящика — переменные окружения `SMTP_USER`/`SMTP_PASS` в конфиге php-fpm пула на сервере, как и `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` — **не в репозитории и не в git**.
  **Важно**: запрос к Telegram идёт не напрямую на `api.telegram.org`, а через Cloudflare Worker-релей (`https://abra-telegram-relay.artemutyashev.workers.dev`, исходники не в этом репо — редактируется через дашборд Cloudflare) — у хостера VPS (FirstByte) весь исходящий трафик на подсеть Telegram блокируется на сетевом уровне (timeout по всем IP, v4 и v6), остальной интернет с сервера при этом работает нормально. Воркер — узкий проброс пути/тела запроса именно на `api.telegram.org`, без хранения секретов и без произвольного целевого хоста (не открытый прокси). Если однажды блокировка со стороны хостера снимется, можно вернуть прямой вызов `api.telegram.org` в `server/contact.php` и убрать воркер — но не делай это неявно, пока владелец не подтвердит, что блокировки больше нет
- Обработка ответа на фронте различает два формата (тот же контракт, что был у Formspree, чтобы не трогать фронтовую логику): `errors[]` (разбор по полям — показываем посетителю) и `error` (строка — уходит в `console.error` вместе с HTTP-статусом, посетителю не показывается)
- Чекбоксы мессенджеров — `name="messenger[]"` (со скобками, изменено при переезде 12.09.2026): без скобок голый PHP-парсер `$_POST` видит только последний отмеченный чекбокс при одинаковом имени, а не оба сразу — Formspree с обоими вариантами имени работал одинаково, поэтому раньше разницы не было видно
- Перед отправкой `contact-modal.js` дописывает в `FormData` поле `ym_client_id` — ClientID Яндекс.Метрики, полученный через `ym(111833820, 'getClientID', callback)` (добавлено 13.09.2026, `getYandexClientId()` в `contact-modal.js`). Вызов асинхронный и не гарантирован (блокировщики рекламы, медленная загрузка счётчика), поэтому обёрнут в `Promise` с таймаутом 1500мс — если Метрика не ответила вовремя или не загрузилась вообще, поле просто не добавляется и заявка всё равно уходит. `contact.php` пишет его в лог и, если оно есть, добавляет строку в письмо и Telegram-уведомление — по этому ClientID заявку можно найти в самой Метрике (Вебвизор, отчёт по посетителю)
- Туда же (добавлено 13.09.2026) уходят `time_on_site_seconds` (секунды между `pageLoadedAt = Date.now()`, выставленным при загрузке `contact-modal.js`, и моментом сабмита) и любые из `utm_source`/`utm_medium`/`utm_campaign`/`utm_content`/`utm_term`, если они были в адресной строке при заходе (`getUtmParams()` в `contact-modal.js`, читает `location.search` один раз при сабмите — если посетитель успел уйти со страницы и вернуться без меток, их уже не будет). `contact.php` собирает оба письма (mail + Telegram) из одного общего `$detailsText`, чтобы новое поле не забыть добавить в одно из двух мест
- Каждая заявка получает порядковый номер (добавлено 13.09.2026) — отдельный файл-счётчик `/var/log/abra-contact/counter.txt` на сервере, инкремент под `flock`, чтобы две одновременные заявки не получили одинаковый номер. Не в git, живёт только на сервере (как и `submissions.log`). Номер уходит в тему письма и в первую строку Telegram-сообщения («Новая заявка №N с a-bra.ru»); если по какой-то причине не удалось открыть/заблокировать файл счётчика, заявка всё равно проходит, просто без номера — это best-effort, не блокирует сохранение в лог
- Геолокация по IP (добавлено 13.09.2026) — best-effort запрос к `ipwho.is` (бесплатный, без ключа, HTTPS) прямо из `contact.php`, 3-секундный таймаут. В отличие от Telegram у этого сервиса нет блокировки со стороны хостера, но выявилась смежная проблема: **у этого VPS в принципе битый исходящий IPv6** — не только до Telegram, а до любого хоста с AAAA-записью. `curl` не страдает (параллелит v4/v6, Happy Eyeballs), а `file_get_contents` пробует последовательно и не укладывается в вменяемый таймаут, виснув на IPv6 на ~2-3 секунды. Поэтому geo-запрос резолвит `ipwho.is` вручную через `gethostbyname()` (только A-записи) и стучится сразу на IPv4-адрес, оставляя исходное имя в `Host`-заголовке и SNI (`ssl.peer_name`) для TLS. **Если в будущем понадобится ещё один внешний HTTP-вызов из `contact.php`, закладывайся на этот же битый IPv6** — либо резолвь вручную как здесь, либо проверяй хост на IPv6-таймаут отдельно, как с Telegram. Строка вида «Город, Страна (провайдер)» пишется в `geo` в логе и, если непустая, строкой в письмо/Telegram
- `data-state="loading"` на кнопке во время запроса — блокирует повторный submit визуально и через `pointer-events:none` в CSS

## Калькулятор юнит-экономики (`unit-economics.html` + `src/unit-economics.js`)

- Подсказки «?» (45 штук): **открытие висит на `click`, закрытие — на `pointerdown`**. Разведено намеренно. `pointerdown` нужен для закрытия, потому что срабатывает раньше и переживает клики внутри `<label>`, где `click` иногда съедается пересылкой фокуса на input. Но активация кнопки с клавиатуры (Enter/пробел) порождает `click` и **не** порождает `pointerdown` — пока открытие висело на `pointerdown`, с клавиатуры не открывалась ни одна подсказка. Не объединять обратно
- На кнопках `aria-expanded` и `aria-describedby="info-tip"`, Escape закрывает и возвращает фокус на кнопку, с которой открыли
- **ROI выводится кратностью (`3,54 ×`), а не процентом.** Формула — `валовая прибыль / расходы на привлечение`, то есть «во сколько раз», и `354,5 %` для той же величины читается как «+354 % к вложенному» — это другая цифра. Если когда-нибудь понадобится процент, надо переходить на ROMI с формулой `(прибыль − затраты) / затраты` и переименовывать метрику. Смесь недопустима
- Процентные поля подписаны единицей («CTR, %», «Маржа, %») — раньше по значению `3` нельзя было понять, 3 % это или 0,03
- Денежные значения склеены с «₽» неразрывным пробелом, `.stat-card__value` — `white-space: nowrap` и `clamp()` по размеру: иначе сетка сжимала карточку и знак валюты уезжал на отдельную строку
- Таблица чувствительности шире 1400px внутри `overflow-x:auto`: у контейнера `tabindex="0"`, `role="region"` и `aria-label`, у правого края градиент-затухание, у заголовка подпись «→ таблица прокручивается вбок»

## Безопасность / CSP

CSP выставляется **через реальный HTTP-заголовок**, а не через `<meta http-equiv>` — meta-тег игнорирует `frame-ancestors` и `form-action`, поэтому только так. С 12.09.2026 источник правды — `/etc/nginx/snippets/security-headers.conf` на сервере (не Cloudflare Pages, он больше не хостит сайт); `public/_headers` в репозитории держится в синхроне как справочник, но сам ни на что не влияет — при правке одного обязательно поправить и второй. `metrica.js` — отдельный ES-модуль именно для того, чтобы Яндекс.Метрику можно было подключать без `unsafe-inline` в `script-src`.

Если меняешь домены в CSP — не забудь `mc.yandex.ru`, `mc.webvisor.org/com` (Метрика), `fonts.googleapis.com/gstatic.com` (шрифты). `formspree.io` убран из `connect-src`/`form-action` 12.09.2026 вместе с переездом формы на свой `/contact.php` — если видишь его в CSP где-то ещё, это забытый хвост.

## Деплой

**Переезд с Cloudflare Pages на собственный VPS завершён 12.09.2026** (причины и разбор вариантов — история решения, сам процесс переезда описан ниже фактами).

- **Основной таргет**: VPS FirstByte, Москва, IP `157.228.191.32`, Ubuntu 24.04, nginx + php-fpm. Автодеплой: push в `main` → GitHub Actions (`.github/workflows/deploy-vps.yml`) собирает `npm run build` и синкает `dist/` по SSH на сервер
  - Деплоит **непривилегированный** пользователь `deploy` (не root, без sudo), у которого есть доступ на запись только в `/var/www/a-bra.ru`. Ключ для него — отдельный (`DEPLOY_SSH_KEY_B64`, secret репозитория, base64 — чтобы не ловить порчу переносов строк при вставке в веб-форму GitHub). Root-ключ для ручного администрирования сервера (nginx, TLS, пакеты) — только на машине владельца, в GitHub никогда не попадает. Это осознанное разделение: утечка деплой-ключа даёт максимум подмену статики сайта, не root
  - `server/contact.php` в репозитории — это копия того, что реально исполняется на сервере (`/opt/abra/contact.php`). CI его **не** деплоит и не должен: исполняемый серверный PHP-код сознательно не передаётся через тот же низкопривилегированный автоматический пайплайн, что и статика — обновляется вручную (`scp` + `php -l` на сервере), при изменении логики формы
  - nginx-конфиг (`/etc/nginx/sites-available/a-bra.ru.conf` + `/etc/nginx/snippets/security-headers.conf` на сервере) — не в репозитории, это инфраструктурное состояние сервера, не кода. `public/_headers`/`public/_redirects` в репозитории остались как справочник того, что должно быть воспроизведено в nginx (Cloudflare Pages их больше не читает — сайт там больше не хостится), при правке одного сверяться со вторым
  - TLS — Let's Encrypt через certbot, автопродление через systemd-таймер на сервере, трогать не нужно
- **Резервный таргет**: GitHub Pages, переключается через `DEPLOY_TARGET=gh-pages` env var в `vite.config.js` (меняет `base` с `/` на `/abra/`) — держится явно как fallback по решению owner'а, не удалять. Никак не связан с переездом на VPS, работает как раньше
- **Внутренние ссылки на страницы пишутся через `%BASE_URL%`**, а не абсолютным путём: `href="%BASE_URL%privacy"`, `href="%BASE_URL%"` для корня. Vite подставляет туда текущий `base` — `/` и для VPS, и для Cloudflare (домен один и тот же, base-путь не менялся), `/abra/` для GitHub Pages. Абсолютный `href="/privacy"` Vite не переписывает, и на резервном таргете такая ссылка уходит в корень домена, то есть в никуда. Пути к картинкам и иконкам Vite переписывает сам, их трогать не нужно
- После каждого push в `main` проверяй, что прод реально обновился: `curl -s https://a-bra.ru/ | grep -o 'assets/main-[^"]*\.js'` и сравни хэш с локальным `npm run build`
- `npm run dev` / `npm run build` / `npm run preview` — стандартные Vite-команды, ничего кастомного

## Как работать над этим проектом

- Все правки в CSS/JS собираются через `npm run build`, визуально проверяются через dev-сервер перед деплоем — это уже устоявшийся паттерн в истории проекта, не пропускай визуальную проверку ради скорости
- После push — обязательно дождаться реального деплоя на VPS (проверить прогон `.github/workflows/deploy-vps.yml` через `gh run list` и хэш бандла), не полагаться на "должно задеплоиться"
- Owner общается по-русски, весь UI-контент на русском — пиши коммиты на английском (уже сложившийся стиль в истории), но комментарии/объяснения в диалоге — по-русски
- Owner любит быстрые точечные правки с проверкой на нескольких viewport (1440/1024/768/390/375/320 — стандартный набор, использовавшийся во всех предыдущих задачах по адаптиву)
- Ничего не добавляй "про запас" — каждая деталь дизайн-системы (скобки, точка перед названием, убранная стрелка, немедленный уход плейсхолдера) — результат явного запроса owner'а, а не дефолт по вкусу. Если сомневаешься, ссылайся на этот файл, а не придумывай заново.
- `npm test` — перед каждым коммитом, который трогает шапку, панель, шторку, кнопки или карточки: сборка, проверки разметки во всех 10 файлах и браузерные проверки на шести ширинах. Нужны Node ≥22 и Google Chrome (путь переопределяется `CHROME_PATH`)
