# ABRAXUS MOTION

Первая коллекция анимированных эмодзи на знаке ABRA для Telegram (custom emoji).
Это отдельная папка: к сайту не подключается, в сборку Vite не попадает.
`src/tokens.js` и `src/motion.js` вписывает в плагин Hermes
`hermes-theme/extended/build.mjs` — ORBITAL стоит в строке статуса, AXIAL · Y —
в шапке страницы ABRAXUS, CORE — на заставке нового чата. После правки здесь — перезапустить его (см.
`hermes-theme/extended/INSTALL.md`, «Обновить»). Обёртку `(function (root) {
… })(typeof window !== "undefined" ? window : globalThis)` не менять: сборка
плагина подменяет её аргумент.

## Быстрый старт

```bash
node abra-motion/scripts/export.mjs     # перерендерить и проверить все WEBM и PNG
python3 -m http.server 8766 --directory abra-motion   # затем http://localhost:8766/preview/
```

Предпросмотр также открывается без сервера двойным кликом по
`preview/index.html` — живые анимации работают и с `file://`. Видео WEBM
в отдельной строке Chrome может не показать с `file://`, тогда нужен сервер.
В `.claude/launch.json` для этого есть конфиг `abra-motion`.

Нужны Node ≥ 22, Google Chrome (путь меняется через `CHROME_PATH`), ffmpeg и
ffprobe с libvpx (`brew install ffmpeg`).

## Структура

```
assets/mark.svg        — копия public/mark.svg, побайтно; экспорт сверяет обе
src/tokens.js          — все параметры: цвета, толщина, длительности, орбита
src/motion.js          — три анимации как чистые функции frame(variant, t) → SVG
preview/index.html     — локальная страница сравнения
scripts/export.mjs     — рендер, кодирование, проверка
export/telegram/*.webm — файлы для @Stickers
export/static/*.png    — кадр 0 каждого варианта и исходный знак, 100 и 512 px
export/report.json     — результат последней проверки по каждому файлу
```

## Как устроено

Каждая анимация — функция от доли цикла `t ∈ [0, 1)`, без состояния и
таймеров. Отсюда:

- **цикл бесшовный по построению**: все кривые движения периодичны,
  `frame(v, 1) === frame(v, 0)` побайтно;
- **предпросмотр и экспорт рисуют одним кодом**: страница вызывает `frame()`
  по `requestAnimationFrame`, экспорт — для каждого из 84 кадров в
  headless Chrome;
- **всё редактируется в одном месте**: длительности, толщины, параметры орбиты и камеры —
  в `src/tokens.js`, после правки — перезапуск экспорта.

Почему SVG + Chrome + ffmpeg, а не Remotion/Lottie/Canvas: знак — один
векторный контур, анимации — поворот с проекцией и движение по окружности. Это
десятки строк геометрии; Remotion добавил бы React и сборщик ради тех же
кадров, Canvas потребовал бы переписать отрисовку контура. Chrome уже нужен
проекту для `npm test`, ffmpeg — единственная новая системная зависимость.
npm-зависимостей нет.

## Геометрия знака

Контур взят дословно из `public/mark.svg`:

```
M 6 155 L 82 75 A 44 44 0 1 0 18 75 L 94 155 Z
```

Нога → петля (дуга r = 44, 267°) → нога → основание. Знак симметричен
относительно x = 50. Центр вращения — центр наименьшей описанной окружности
на оси симметрии, (50; 84,18), радиус с учётом толщины линии — 89,4. Через
эту точку проходит ось AXIAL · Y, поэтому знак не задевает край кадра ни
при каком угле.

`motion.js` не хранит координат: он разбирает строку `d` из токенов, а
экспорт перед рендером проверяет, что строка совпадает с `public/mark.svg`.
ORBITAL рисует именно эту строку `d`, без пересборки. AXIAL·Y проецирует те же вершины, а дугу — по выборке через
каждую единицу знака: при проекции прямые остаются прямыми, искажения нет.

**Толщина линии — 12 единиц.** На сайте она зависит от размера показа: 6 в
`mark.svg`, 10 в шапке и футере, 11 во вкладке нижней панели, 12 в
`favicon.svg` (самый мелкий показ). Эмодзи живёт в 20–24 px, поэтому взят
вес favicon. Меняется в `tokens.mark.stroke`.

## Три анимации

| | Что происходит | Цикл | Чем отличается |
|---|---|---|---|
| **01 AXIAL · Y** | Монета: поворот вокруг вертикальной оси симметрии с перспективой ±10 % | 2,8 с, 84 кадра | Знак симметричен, поэтому лицевая и обратная стороны одинаковы — за цикл знак дважды «раскрывается». Скорость модулирована: дольше на лицевой стороне, быстро через ребро |
| **02 ORBITAL** | Знак неподвижен, по тонкому кольцу идёт маркер с коротким затухающим следом | 2,8 с, 84 кадра | Самый спокойный. Знак мельче (64 % высоты кадра против 87 % у AXIAL · Y) — кольцу нужно место |
| **03 CORE** | AXIAL · Y внутри ORBITAL: знак поворачивается монетой, вокруг идёт маркер | 2,8 с, 84 кадра | Монета ортографическая (без перспективы): сжатая дуга — дуга эллипса, кадр — короткая строка `d`. Поэтому CORE есть и одним SVG со встроенной анимацией — `AbraMotion.animated('core')`, это заставка нового чата в Hermes. WEBM для Telegram появится при следующем запуске `export.mjs` |

### Узнаваемость при повороте (AXIAL · Y)

Около 90° и 270° знак сходится в вертикальную линию — это неизбежно для
плоского знака на ребре. Толщина линии при этом не проецируется, поэтому
знак не исчезает до нуля, а модуляция скорости (`axialY.dwell = −0,3`)
проходит участок ±15° вокруг ребра примерно за 0,3 с из 2,8. Если в чате это будет мигать —
увеличить `|dwell|` (до 0,45).

### Читаемость в 20–24 px

Проверено даунскейлом готовых WEBM до 24 px:
- AXIAL · Y читается полностью;
- ORBITAL: маркер читается, кольцо почти растворяется — так задумано, главный
  объект — знак.

## Цвета

Все из `:root` в `src/style.css`, экспорт сверяет HEX перед рендером:

| Токен сайта | HEX | Где |
|---|---|---|
| `--accent` | `#B87333` | знак, кольцо и маркер (кольцо 32 %, след до 50 %) |
| `--bg` | `#0C0B09` | только фон предпросмотра |

Новых цветов нет. `#FFFFFF` в предпросмотре — фон светлой темы Telegram, а
не токен.

### Расхождения палитр (на сайте ничего не меняли)

- **Каноническая бренд-платформа ABRA в репозитории и в `~/Documents` не
  найдена** — сверить с ней не удалось. Если она есть отдельным файлом,
  её стоит положить рядом и прогнать сверку.
- `abra-tokens.css` (блок `[TARGET]`) и `hermes-theme/tokens.json` содержат
  функциональные цвета ok / warn / bad / info (`#7C9A6E`, `#C9A24B`,
  `#B5563F`, `#6E86A0`), которых на работающем сайте нет. В эмодзи они не
  используются.
- Толщина линии знака на сайте разная в разных местах (6 / 10 / 11 / 12) —
  см. «Геометрия знака».

## Telegram

Требования сверены с <https://core.telegram.org/stickers> 9 октября 2026
(раздел о видеостикерах и видеоэмодзи):

| Требование | Как проверяется | Результат |
|---|---|---|
| WEBM, VP9 | ffprobe: контейнер и кодек | ✓ оба |
| ровно 100×100 | ffprobe | ✓ |
| до 30 FPS | ffprobe `r_frame_rate` | ✓ 30 |
| до 3 с | ffprobe `duration` | ✓ 2,8 / 2,8 |
| до 256 КБ | размер файла | ✓ 20–45 КБ |
| без звука | ffprobe: ровно один поток, видео | ✓ |
| цикл | разница последнего и первого кадра ≤ обычной разницы соседних кадров | ✓ |
| прозрачность | флаг `ALPHA_MODE=1` **и** декодирование libvpx-vp9 в RGBA: ~80 % пикселей с альфой 0, углы прозрачны во всех кадрах, есть непрозрачные | ✓ |

Об альфе: ffprobe показывает `pix_fmt=yuv420p` даже у прозрачного VP9 — альфа
в WEBM лежит отдельным слоем (BlockAdditional), и встроенный декодер ffmpeg
её не читает. Поэтому проверка декодирует файл именно `libvpx-vp9` и считает
пиксели, а не смотрит на имя формата.

Официальная страница не требует прозрачности для видео прямо — она нужна по
смыслу: эмодзи стоит в тексте поверх фона чата.

### TGS как альтернатива (оценка, не реализовано)

TGS (Lottie): холст 512×512, 60 FPS, до 3 с, до 64 КБ.
- ORBITAL переносится в Lottie один к одному: контур + движение по
  окружности. Векторный TGS был бы резче на ретине, чем
  100-пиксельный WEBM.
- AXIAL · Y — перспективная проекция в Lottie для Telegram ограничена
  (3D-слои поддерживаются плохо), пришлось бы запекать покадровые пути и
  упираться в 64 КБ.

AXIAL · Z (плоский оборот) и REBUILD (перестройка маршрута) были в первой
итерации и удалены по решению владельца 9 октября 2026 — остались два
варианта.

Вывод: для первой версии WEBM проще и надёжнее; TGS имеет смысл для
ORBITAL, если понадобится максимальная резкость.

## Загрузка в Telegram (после утверждения — не выполнялось)

В @Stickers: `/newemojipack` → тип «Видео» → название набора → по одному
файлу из `export/telegram/` с эмодзи-привязкой → `/publish` → короткое имя
набора. Перед загрузкой — перезапустить `export.mjs`, все строки должны
быть с ✓.

## Дальнейшее использование

`motion.js` не зависит ни от DOM, ни от Telegram: `AbraMotion.frame(key, t,
size)` отдаёт SVG-строку. Для сайта или Hermes Desktop достаточно вызывать
её по `requestAnimationFrame` (с уважением к `prefers-reduced-motion` —
тогда `t = 0`). Так и сделано в Hermes Desktop (плагин ABRAXUS Extended).
