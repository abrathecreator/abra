# ABRAXUS STANDARD v1.0

Фирменный скин Hermes на дизайн-токенах a-bra.ru — только штатный YAML-механизм. Без customCSS, без Desktop-плагина, без правки Hermes и `app.asar`, без сторонних зависимостей.

| Файл | Что это |
|---|---|
| `abraxus.yaml` | сам скин — единственное, что ставится в Hermes |
| `check.py` | автоматические проверки (структура, токены, движок Hermes, контраст, терминалы) |
| `preview.html` | визуальное превью: палитра, CLI, TUI, Desktop, варианты — открыть в браузере |
| `INSTALL.md` | ручная установка, откат, удаление |

Проверено на Hermes Agent `489c1ac` (2026.9.24).

## Проверки

```bash
~/.hermes/hermes-agent/venv/bin/python ~/Documents/abrasite/hermes-theme/standard/check.py
```

Запускается интерпретатором Hermes: там уже есть `ruamel.yaml` и `rich`, которыми Hermes сам читает и рисует скин. Другой путь к Hermes — `HERMES_AGENT_DIR=...`. Что проверяется:

1. **Токены** — каждое базовое значение в `../tokens.json` действительно стоит в `src/style.css` или `abra-tokens.css`; каждая производная равна своей формуле смешивания.
2. **Структура** — только документированные ключи; заданы все 44 цветовых токена из канонического контракта `apps/shared/src/skin.ts`, все 6 ключей branding, все 4 ключа spinner; нет `customCSS`; имя, описание и размер проходят фильтры загрузчика Desktop.
3. **Ссылки** — у каждого цвета есть `# token: <имя>`, и значение совпадает с токеном; цвета внутри логотипа — тоже из токенов.
4. **Движок** — скин грузится настоящим `hermes_cli/skin_engine.py` из временного `HERMES_HOME`, без отката на default; строятся стили prompt_toolkit для CLI.
5. **Контраст** — текст ≥ 4,5:1, линии элементов управления ≥ 3:1, каждая пара — с фоном, на котором её реально рисуют.
6. **Терминалы** — в коротких элементах только «узкие» символы (East Asian Width N/Na); логотип и знак — по одной цветной группе на строку (иначе парсер TUI порвёт строку), ширина 57 и 19 колонок, Rich и TUI показывают одинаковый текст.

## Решения и ограничения

- **Только тёмная тема.** Скин задаёт `background`, поэтому TUI всегда берёт тёмную полярность и `light_colors` не применил бы; CLI и Desktop эти блоки не читают вовсе. Светлый вариант на «печатных» токенах возможен только в EXTENDED.
- **Классический CLI не перекрашивает фон терминала** — на светлом профиле текст `#CEC9C3` будет бледным. Для CLI нужен тёмный профиль (TUI красит фон сам).
- **`completion_menu_bg` = `#2B2927`.** Этот ключ в CLI/TUI — фон меню, а в Desktop — обводка полей и чекбоксов. Взят край плашек сайта: меню читается (8,8:1), а обводка полей в Desktop — как остальные рамки, 1,36:1. На сайте чекбоксы обведены `--border-control` 3,15:1; вернуть это в Desktop можно только в EXTENDED.
- **Кнопка-заливка в Desktop** затемняется самим Hermes до `#935C29` ради белого текста — медь в чистом виде на «громких» кнопках будет только в EXTENDED.
- **TUI поднимает линии** `ui_border` с `#2B2927` до `#413F3D` — его встроенный порог видимости 1,45:1.
- **Что скином не меняется:** значок ☤ и подпись «Nous Research · Посланник цифровых богов» под логотипом TUI, кадры анимации спиннера (⠋⠙⠹), шрифты, иконки, раскладка.
- **Ошибка — `#C07460`, а не `#B5563F`.** `--abra-bad` текстом даёт 4,09:1 — ниже нормы; `bad-text` — тот же цвет, поднятый к `--snow` до 5,54:1. Заливки diff используют исходный `--abra-bad`.
- **`agent_name` уходит в релей ботов** — см. INSTALL.md.
- **Блочные буквы логотипа** (`█╗║═`) — символы неоднозначной ширины, как и у встроенного логотипа Hermes. В терминале, где такие символы настроены «широкими» (бывает в CJK-локалях), логотип разъедется — тогда вариант C ниже.

## Варианты

В скине стоит по одному варианту, остальные показаны в `preview.html`. Чтобы переключить — заменить строки в `abraxus.yaml` и прогнать `check.py`.

**Брендинг** (`branding` + `tool_prefix`)

| | A · System Core (в скине) | B · Сигнатура | C · Минимал ASCII |
|---|---|---|---|
| `agent_name` | `ABRAXUS` | `ABRAXUS System Core` | `ABRAXUS` |
| `response_label` | `" [ .ABRAXUS ] "` | `" [ .SYSTEM CORE ] "` | `" ABRAXUS "` |
| `prompt_symbol` | `›` | `▸` | `>` |
| `help_header` | `[ .Команды ]` | `[ .Команды ядра ]` | `Команды` |
| `goodbye` | `[ .Сессия сохранена ]` | `[ .Ядро остановлено ]` | `До связи.` |
| `tool_prefix` | `╎` | `╎` | `\|` |

Для C стоит удалить `banner_logo` и `banner_hero` — тогда Hermes покажет встроенные.

**Приветствие** (`welcome`, видно только в классическом CLI)

- A (в скине): `ABRAXUS / SYSTEM CORE на связи. Опишите задачу или введите /help.`
- B: `[ .Система готова ] Маркетинг, продажи, аналитика или продукт — с чего начнём? /help — команды.`
- C: `ABRAXUS / SYSTEM CORE online. Describe the task or type /help.`

| `thinking_faces` | `[ ◦ ]` `[ ∘ ]` `[ ▪ ]` `[ ▫ ]` | `◌` `◦` `∘` | `▸` `▪` `▫` |
| `wings` | `["[ .", "]"]` | `["⟨", "⟩"]` | `["›", "‹"]` |

Глаголы общие. В скине — русские: собираю систему, ищу узкое место, сверяю воронку, считаю юнит-экономику, связываю маркетинг и продажи, раскладываю по слоям, проверяю гипотезу, свожу данные, выстраиваю маршрут, калибрую метрики. Английская замена: assembling the system, finding the bottleneck, checking the funnel, running unit economics, linking marketing and sales, mapping the layers, testing the hypothesis, reconciling data, plotting the route, calibrating metrics. Без `thinking_verbs` Hermes берёт глаголы из своего каталога на языке интерфейса.
